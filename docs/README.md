# OctoAcme Project Management Docs

This README is the entry point for OctoAcme’s project management documentation in `docs/`.  
It summarizes the delivery approach and links to each process guide so team members can quickly find what they need.

## Brief Overview of OctoAcme Project Management Processes

OctoAcme uses a lightweight, iterative model that moves through **initiation, planning, execution, release, and continuous improvement**. During initiation, teams define the business problem, goals, success metrics, stakeholders, initial risks, and a go/no-go decision.

In planning, teams create a prioritized backlog with clear acceptance criteria, estimate work, define milestones, identify dependencies, and align on a Definition of Done. Execution is managed through regular team rhythms (standups, weekly syncs, demos), project board workflow states, and disciplined pull request practices.

Quality assurance is built into delivery through CI checks, unit/integration testing, smoke testing for critical flows, and security scanning. Risk and communication practices include structured updates, risk-register tracking, and clear escalation paths. After releases, retrospectives capture learnings and convert them into actionable, owned improvements.
